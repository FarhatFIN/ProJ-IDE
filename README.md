# ProJ IDE v3 — C++-движок + веб-интерфейс, два способа запуска

Движок целиком в C++ (сборка, проекты, файлы, установка компиляторов). Интерфейс
веб (Monaco локально, без CDN и Node), и подаётся он двумя способами:

1. **Настольное приложение** (основной способ): `./projide-app` — своё окно
   GTK3 + WebKitGTK поверх встроенного сервера. Один процесс, своё окно, без
   браузера. Ярлык в меню: `./install-desktop.sh`.
2. **Сайт-режим**: `./projide` — тот же движок поднимает сервер на
   `127.0.0.1:<порт>` и открывает браузер (`--no-browser` — не открывать).

```bash
./build.sh      # projide     — серверный вариант, без зависимостей
./build-app.sh  # projide-app — настольное окно (нужен libwebkit2gtk-4.1-dev)
./install-desktop.sh          # ярлык «ProJ IDE» в меню приложений
```

Файлы первого запуска: `~/ProJ-IDE-Projects/hello/` с демо-проектом.
Список проектов: `~/.config/proj-ide/projects.txt` (открытый текст).

## Что в интерфейсе

- **Титульная панель**: ProJ IDE · поиск-палитра (Ctrl+P) · зелёный «▶ Старт».
- **Activity-бар**: ☰ Проводник · ▶ Запуск (описание инструмента + «Запуск в терминале») · ⚙ Настройки (Тёмная/Светлая/Системная).
- **Дерево проектов**: нумерация `1. 2. 3.`, раскрытие по клику + авто-открытие последнего файла (точка ●), цвет иконки по языку, действия по ховеру/в дереве: новый файл, добавить файлы (контент уходит на сервер, файлы создаются в `~/ProJ-IDE-Projects/<проект>/`), убрать из проекта, удалить проект (с диска не сносится).
- **Monaco**: подсветка C/C++/Python/Markdown, миникарта, цветные скобки, ligatures, темы proj-dark/proj-light.
- **Вкладки**: метка изменений точкой, ПКМ/крестик — закрыть.
- **Запуск (Ctrl+B / Ctrl+R / Ctrl+Enter)** — единственная кнопка действия: сохранить → скомпилировать → выполнить живьём в панели «Вывод». Ошибки компиляции — в Monaco-маркеры и «Проблемы»; успех — программа Attached к панели: её stdout/stderr стримится, внизу строка ввода — печатаешь, Enter отправляет программе stdin, как в терминале. «■ Стоп» убивает процесс. Python: сборка = py_compile-проверка, исполнение — в живом раннере.
- **Бинарная защита**: файл с NUL в первых 8 КБ не открывается как текст («бинарный файл»).
- **Нет компилятора** → «У вас не нашлось "g++"… Разрешаю?» → сервер ставит из доверенной таблицы (apt/dnf/winget/xcode-select) с прогрессом «Загружаем… N%» → нет сети → «Ошибка сети».
- **Диалог ошибки**: «Ошибка компиляции — строка N» + «Перейти».
- **Статус-бар**: ✖/⚠ (клик — Проблемы) · Стр/стлб live · UTF-8 · язык.
- **Палитра Ctrl+P**: фильтр по имени файла и проекту, ↑↓/клик — открыть.

## Архитектура

```
projide / projide-app (C++20, ~290 КБ)
├─ http.{hpp,cpp}    свой HTTP/1.1: keep-alive, thread-per-connection, 127.0.0.1
├─ jsonlite.{hpp,cpp} JSON writer/parser без зависимостей
├─ api.{hpp,cpp}     /api/state|open|save|build|newproject|addfiles|newfile|
│                    deleteproject|deletefile|installcheck|install|installstatus
│                    /api/runlive|proc/write|proc/read|proc/kill
├─ build/lang/store/install/util — движок
├─ liveproc.{hpp,cpp} живой интерактивный процесс (stdin/stdout, чанки, kill)
├─ embed.{hpp,cpp}   веб-UI, вшитый в бинарник (ustar в памяти)
├─ server_main.cpp   серверный вариант: порт + системный браузер
└─ shell_main.cpp    настольный вариант: GTK3-окно + WebKitGTK (src_shell/)

web/                 фронтенд (статика, отдаётся сервером)
├─ index.html / app.css / app.js   vanilla-порт Ide.tsx: ~800 строк JS
└─ monaco/vs         Monaco 0.52.2 (14 МБ) — локально
```

Безопасность: сервер слушает только loopback; open/save/build принимают пути,
зарегистрированные в проектах; имена загружаемых файлов чистятся от `/ \ ..`.

## Сборка

- `./build.sh` — серверный вариант: **полностью статический** бинарник, веб-UI (вместе с Monaco) вшит внутрь tar'ом, никаких зависимостей на целевой машине.
- `./build-app.sh` — **настольное приложение** (libwebkit2gtk-4.1-dev).
- `./build-fltk.sh` — старый FLTK-вариант (libfltk1.3-dev).
- `./install-desktop.sh` — ярлык в меню приложений.

## Пакеты (./package.sh)

| Файл | Куда | Состав |
|---|---|---|
| `dist/projide_1.0.0_amd64.deb` | Debian / Kali / Ubuntu | `projide` (статический, сервер+браузер) + `projide-app` (окно GTK/WebKit) + ярлык; Depends: libwebkit2gtk-4.1-0, libgtk-3-0 |
| `dist/projide-1.0.0-1.x86_64.rpm` | Fedora | те же файлы; Requires: webkit2gtk4.1, gtk3 |
| `dist/ProjIDE-win64.zip` → `ProJ-IDE.exe` | Windows 10/11 x64 | самодостаточный exe (веб-UI вшит), при запуске поднимает сервер и открывает браузер |

Установка: `sudo dpkg -i projide_1.0.0_amd64.deb` / `sudo dnf install ./projide-1.0.0-1.x86_64.rpm` / распаковать zip и запустить exe.

Честные ограничения:
- `projide-app` в deb/rpm динамический (нужен системный WebKitGTK) и собран на Kali rolling — на дистрибутиве со заметно более старым glibc берите `projide` (статический, работает везде).
- Windows-вариант: сборка и вывод компилятора работают, интерактивный живой ввод (liveproc) — POSIX-заглушка, будет портирован на CreateProcess-пайпы.
- exe не подписан и не гонялся на живой Windows (кросс-сборка mingw) — при первом запуске SmartScreen может спросить разрешение.

## Проверено

- curl-тесты API: state / open / save / build (успех, ошибка с line:col, python+stdin) / newproject / addfiles.
- Вживую в браузере: дерево, открытие файлов, вкладки, сборка fail.cpp → диалог «Ошибка компиляции — строка 2» → «Перейти» → курсор [2,12] (статус-бар), маркеры Monaco + миникарта, Проблемы 1, Errors<1> красный, палитра с фильтром «calc».
- Python со stdin через exec-пайп (юнит-тест), ошибка парсинга локалей исключена (`LC_ALL=C`).
- Windows/macOS: ветки http-сервера (winsock) и запуска браузера собраны, на живой машине не прогонялись.
