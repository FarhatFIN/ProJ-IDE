# ProJ IDE

Полностью нативный компактный IDE на C++ (FLTK). Один процесс, своё окно,
локальные файлы, без HTTP-сервера, без браузера, без HTML. Работает с
g++/gcc/nasm/python3 и gdb.

## Возможности

- **Проекты**: «Новый проект» (файлы + имя), нумерованный список `1. 2. 3.…`,
  клик раскрывает файлы и открывает последний редактировавшийся (метка ●).
- **Импорт GitHub**: кнопка «Импорт GitHub» → URL → `git clone --depth 1` →
  все текстовые файлы репозитория становятся проектом (бинарники и мусорные
  каталоги .git/node_modules/__pycache__ пропускаются).
- **Импорт папки**: кнопка «Папка» → нативный выбор каталога → все текстовые
  файлы дерева (≤4 МБ, без NUL) регистрируются как проект.
- **Редактор**: подсветка C/C++/Python/Markdown, номера строк, вкладки с
  меткой изменений, хлебные крошки, палитра файлов Ctrl+P.
- **Запуск (Ctrl+B)**: сохранить → собрать → программа живёт в панели
  «Вывод»: вывод стримится, внизу строка ввода — Enter отправляет строку
  в stdin программы, «■ Стоп» завершает. Промпты видны сразу (stdbuf -oL).
- **Отладка**: сборка с `-g -O0` и gdb в панели «Вывод» (run · break main ·
  n · p var · bt · q); Python — pdb.
- **Real-time детектор ошибок**: правишь код — через секунду
  `-fsyntax-only` / `ast.parse` в фоне, ошибки падают в Errors<N> и список
  проблем; клик — переход к строке. Результаты сборки имеют приоритет.
- **Нет компилятора** → «У вас не нашлось "g++"…» → «Разрешаю» → установка
  из доверенной таблицы с прогрессом; нет сети → «Ошибка сети».
- **Выход**: если есть несохранённые правки — диалог «Сохранить» /
  «Не сохранять».
- **Темы**: Тёмная / Светлая / Системная.

## Сборка

```bash
sudo apt install build-essential libfltk1.3-dev
./build-app.sh   # → ./projide-app
./install-desktop.sh   # ярлык в меню приложений
```

## Пакеты (./package.sh)

| Файл | Куда | Зависимости |
|---|---|---|
| `dist/projide_1.1.0_amd64.deb` | Debian/Kali/Ubuntu | libfltk1.3-0 |
| `dist/projide-1.1.0-1.x86_64.rpm` | Fedora | fltk |

Рекомендуется также build-essential и python3 (ими IDE компилирует твой код).

## Хранилище

`~/.config/proj-ide/projects.txt` — открытый текст:

```
project <имя>
file <путь>
last <последний файл>
```

Файлы не копируются — проект держит ссылки на диске. Импортированные
репозитории и папки кладутся в `~/ProJ-IDE-Projects/<имя>/`.

## Архитектура

```
projide-app (~320 КБ, FLTK)
├─ src/util.{hpp,cpp}       процессы (exec, таймаут, stdin), PATH, сеть
├─ src/lang.{hpp,cpp}       типы файлов, инструменты, доверенные источники
├─ src/build.{hpp,cpp}      сборка, -g/-O0, парсер ошибок gcc/py/nasm, lint
├─ src/store.{hpp,cpp}      проекты (текстовый формат)
├─ src/install.{hpp,cpp}    установка компиляторов с прогрессом
├─ src/liveproc.{hpp,cpp}   живой интерактивный процесс (stdin/stdout/kill)
└─ src_fltk/main.cpp        весь UI: activity-бар, дерево, вкладки, панели
```

## Проверено

- Сборка/запуск C++, C, Python, NASM; интерактив через пайпы (curl-стенд:
  промпт → ввод → ответ → код выхода; падение SIGSEGV → код 139).
- gdb-сессия через liveproc: symbols → break main → run → bt → quit (стенд).
- lint_file: ошибка ловится, чистый файл — ноль находок (стенд).
- git clone + обход дерева (стенд: 26 файлов тестового репозитория).
- Импорт папки, диалоги, темы, палитра, диалог выхода — в UI.

## Известные шрамы

- Debian FLTK со старым ABI: цвета номеров строк — заглушки, гуттер
  перекрашивает свой CodeEditor поверх базовой отрисовки.
- Fl_Pack не перевыкладывает детей после показа — вкладки на ручной раскладке.
- UTF-8: срез строки палитры по em-dash (+3 байта).
- Windows-сборка: FLTK кросс-компилируется, но не проверялась — в планах.
